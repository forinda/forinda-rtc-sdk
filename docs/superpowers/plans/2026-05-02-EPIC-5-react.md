# EPIC-5: `@forinda/video-sdk-react` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the React adapter for the Forinda RTC SDK — hooks (`useUserMedia`, `useDevices`, `usePublisher`, `useViewer`, `useConnectionStats`), an optional `VideoSdkProvider` for shared config, and a `<VideoView>` component that wraps `<video>` with `srcObject` + autoplay quirks. React 18+ only — `useSyncExternalStore` is the foundation.

**Architecture:** Hooks subscribe to the underlying class instances (`Publisher`, `Viewer`, `MediaStream`, `MediaDevices`) via `useSyncExternalStore`, so React tearing is impossible and state stays in sync without manual `useState` + `useEffect` chains in user code. All effects use `AbortController` cleanup so StrictMode double-invocation is idempotent. SSR-safe: hooks early-return inert state on server (`typeof window === "undefined"`); `<VideoView>` renders an empty `<video>`.

**Tech Stack:** TypeScript 6, ESM, React 18, Vitest 2 + jsdom + @testing-library/react, EPIC-3 `@forinda/video-sdk-core`. Already-scaffolded package at `packages/react/` (EPIC-1 baseline).

**Spec reference:** `docs/superpowers/specs/2026-05-02-video-sdk-design.md` — Section 8 (React adapter).

**Project conventions:** factory style for any non-hook helper, hooks named `useX`, inline JSDoc on every src file, `@/*` path alias in tests, tsconfig split, TS 6 import extensions, **thorough package README**.

**Definition of done:**

- All 9 tasks completed with their tests passing.
- `pnpm --filter @forinda/video-sdk-react build typecheck test lint` exits 0.
- Coverage on `src/` ≥ 90% lines.
- Public surface exports `VideoSdkProvider`, `useVideoSdkConfig`, `useUserMedia`, `useDevices`, `usePublisher`, `useViewer`, `useConnectionStats`, `VideoView` plus relevant types.
- Repo tagged `v0.0.0-epic-5`.

**Out of scope (deferred):**

- Server-side rendering of media (impossible by design).
- React Server Components — hooks are client-only by definition.
- React 17 / pre-`useSyncExternalStore` compat shims.
- React Native bindings (separate package, post-v0.1.0).

### Task 1 — Vitest + React testing infrastructure

**Files:** `packages/react/{tsconfig.json, tsconfig.build.json, vitest.config.ts, package.json, tsup.config.ts}`, `packages/react/test/_mocks/{fake-publisher.ts, fake-viewer.ts}`

**Deps to add:** `vitest`, `@vitest/coverage-v8`, `jsdom`, `@types/jsdom`, `@testing-library/react@^16`, `@testing-library/dom`, `@testing-library/jest-dom`. Add `@forinda/video-sdk-core` as devDep (workspace) for tests.

Split tsconfig (json + build.json), `@/*` alias, jsdom env, `jsx: "react-jsx"`. tsup `external: ["react", "react-dom"]`, `dts: true` (not `resolve: true` since react types are huge).

Build fake `Publisher` + `Viewer` substitutes that emit the same events the real classes do — let hook tests drive state without spinning up real WebRTC. Each fake exposes `__emit(event, payload)` for test control.

### Task 2 — `VideoSdkProvider` + `useVideoSdkConfig`

**Files:** `src/provider.tsx`, `test/unit/provider.test.tsx`

```tsx
interface VideoSdkConfig {
  signaling?: () => SignalingTransport;
  iceServers?: RTCIceServer[];
  retry?: RetryConfig;
}

const Ctx = React.createContext<VideoSdkConfig>({});

export function VideoSdkProvider({ children, ...config }: PropsWithChildren<VideoSdkConfig>): JSX.Element { ... }
export function useVideoSdkConfig(): VideoSdkConfig { ... }
```

Provider is **optional** — hooks accept per-call overrides. `signaling` is a **factory** so each hook gets its own transport. Tests: provider supplies defaults; hooks-without-provider get `{}`; per-call overrides win.

### Task 3 — `useUserMedia({audio, video})`

**Files:** `src/use-user-media.ts`, `test/unit/use-user-media.test.tsx`

Hook signature:

```ts
const { stream, error, state, refresh, stop } = useUserMedia(opts);
// state: "idle" | "requesting" | "granted" | "denied" | "error"
```

Calls `getUserMedia(opts)` from core. Cleanup: stops all tracks on unmount. `refresh()` re-requests; `stop()` halts + transitions to `idle`. SSR-safe: returns `{ stream: null, state: "idle" }` on server.

Use `AbortController` to make StrictMode double-invocation idempotent (a stream requested by the first mount that's torn down should NOT leak when the second mount fires).

### Task 4 — `useDevices()`

**Files:** `src/use-devices.ts`, `test/unit/use-devices.test.tsx`

```ts
const { cameras, microphones, speakers, refresh } = useDevices();
```

Subscribes to `watchDevices(cb)` from core via `useSyncExternalStore`. Auto-refresh on `devicechange` events. SSR-safe: returns empty arrays on server.

### Task 5 — `usePublisher(opts)`

**Files:** `src/use-publisher.ts`, `test/unit/use-publisher.test.tsx`

```ts
const {
  publisher,
  state,
  viewers,
  stats,
  error,
  start,
  stop,
  replaceVideoTrack,
  replaceAudioTrack,
} = usePublisher({
  room: "demo",
  stream, // from useUserMedia
  autoStart: true, // default true
  stats: { interval: 1000 },
});
```

Constructs `Publisher` on mount via `definePublisher(...)`. Subscribes to `'state'`, `'viewer'`, `'viewer-left'`, `'stats'`, `'error'` via `useSyncExternalStore` against an internal subscriber that aggregates all events into a snapshot object. `autoStart: true` calls `publisher.start()` once `stream` is available. Tear down on unmount.

Resolves `signaling` and `iceServers` from `useVideoSdkConfig()` if not supplied. Strict-mode safe via `AbortController` cleanup.

### Task 6 — `useViewer(opts)`

**Files:** `src/use-viewer.ts`, `test/unit/use-viewer.test.tsx`

Symmetric to `usePublisher`:

```ts
const { viewer, state, stream, stats, error, start, stop } = useViewer({
  room: "demo",
  publisherId: "alice",
  autoStart: true,
});
```

`stream` is the remote stream, set when first `track` event fires.

### Task 7 — `useConnectionStats(publisherOrViewer, opts?)`

**Files:** `src/use-connection-stats.ts`, `test/unit/use-connection-stats.test.tsx`

```ts
const stats = useConnectionStats(publisherOrViewer, { interval: 500 });
// stats: ConnectionStats[] for publisher, ConnectionStats | null for viewer
```

Standalone hook for consumers managing their own publisher/viewer who want stats. Wraps the same polling shape as `usePublisher`/`useViewer`'s built-in stats option.

### Task 8 — `<VideoView stream={...} />`

**Files:** `src/video-view.tsx`, `test/unit/video-view.test.tsx`

```tsx
<VideoView stream={stream} muted autoPlay playsInline mirror />
```

Wraps `<video>`. On `stream` change, sets `videoEl.srcObject = stream` (which doesn't fit React's prop model). Forwards refs. `mirror` prop applies `transform: scaleX(-1)`. Empty render on SSR.

### Task 9 — Public surface + README + verify + tag

**Files:** `src/index.ts`, `README.md`

Re-export all hooks + components + types. README covers install, quick-start, full hook reference, SSR notes, StrictMode behavior. Then full pipeline + coverage check + `git tag -a v0.0.0-epic-5`.

## Risks and notes

- **`useSyncExternalStore` requires a stable subscribe function.** Wrap in `useCallback` or define module-scope.
- **StrictMode double-mount in dev:** every effect must accept and ignore being torn down between mount→unmount→remount. AbortController is the cleanest pattern.
- **`<VideoView>` ref forwarding:** use `React.forwardRef` so consumers can attach their own ref while keeping the internal `srcObject` assignment working.
- **`jsdom` lacks `RTCPeerConnection` and `MediaStream`:** test fakes from EPIC-3a (`fake-pc.ts`, `fake-media-devices.ts`) carry forward; this package adds `fake-publisher.ts` + `fake-viewer.ts` so hook tests don't need to construct real Publishers/Viewers.
- **`useDevices` and `useUserMedia` early-return on SSR** — but `useSyncExternalStore` itself needs care; provide a no-op `subscribe` and a stable `getServerSnapshot` to avoid hydration mismatches.
- **`<VideoView>` autoplay:** modern browsers block autoplay unless `muted`. Document that consumers wanting `autoPlay` without `muted` need a user gesture.
