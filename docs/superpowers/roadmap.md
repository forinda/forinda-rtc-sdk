# Roadmap — open epics

Backlog of work scoped from the post-EPIC-13 critical review (27 gaps) plus deferred slices from earlier epics. Each row is a self-contained epic with its own plan + tag once executed. Ordering at the bottom is a recommendation, not a hard sequence.

**Gap numbers** below reference the audit list discussed in chat: 1 (`RoomChannel.start` connect guard), 2 (transport sharing → `defineRoom`), 3 (duplicated fake-MediaRecorder), 4 (engine-test setup helper), 5 (`RoomChannel` retry), 6 (optimistic chat echo), 7 (chat sequence numbers), 8 (chat persistence), 9 (recorder upload helper), 10 (engine rate limits), 11 (recorder chunk-buffer cap), 12 (`<forinda-recorder for="…">`), 13 (`useRecorder.downloadUrl`), 14 (presence-diff helper), 15 (`useRoomChannel` state), 16 (chat-input maxLength), 17 (browser tests), 18 (cross-package integration tests), 19 (signaling load test), 20 (CI), 21 (npm publish), 22 (CHANGELOG), 23 (bundle-size budget), 24 (SECURITY.md), 25 (architecture diagram), 26 (patterns guide), 27 (troubleshooting guide).

## EPIC-18 — Polish + test-helpers consolidation (NEW)

**Scope:** Quick wins from the audit. No new features, no architectural shifts — fixes, helper consolidation, small DX upgrades.

**Gaps closed:** 1, 3, 4, 11, 13, 14, 15, 16, 22 (CHANGELOG.md, partial — also done in EPIC-9), 24 (SECURITY.md).

**Depends on:** nothing.

**Size:** S — under one focused session.

**Acceptance:**

- `SECURITY.md` at repo root: how to report WebRTC-related vulns
- `CHANGELOG.md` seeded with prior tags

## EPIC-19 — `defineRoom` higher-level primitive (NEW)

**Scope:** Bundle Publisher / Viewer / RoomChannel under one factory so consumers get media + presence + chat from a single transport without footguns.

**Gaps closed:** 2.

**Depends on:** EPIC-18 (test helpers).

**Size:** M.

**Acceptance:**

- `defineRoom({ signaling, room, peerId? })` returns a `Room` handle exposing `.publisher`, `.viewer`, `.channel`, `.recorder` factories that share the underlying transport correctly (single `join`)
- Publisher / Viewer / RoomChannel constructors accept an optional `room: Room` to attach to instead of self-managing
- React: `useRoom({ room, peerId? })` returning `{ room, status, error }`; `usePublisher` / `useViewer` accept `room?: Room` to skip constructing their own
- Documented migration: existing `definePublisher({ signaling, ... })` calls keep working; `defineRoom` is purely additive
- `<forinda-room>` element wires children automatically

## EPIC-20 — Resilience: RoomChannel retry + optimistic chat (NEW)

**Scope:** `RoomChannel` gets the same `defineRetryPolicy` integration that Publisher / Viewer have. Chat gains optimistic local echo with reconciliation on server ack.

**Gaps closed:** 5, 6.

**Depends on:** EPIC-18.

**Size:** M.

**Acceptance:**

- `defineRoomChannel({ retry: RetryConfig })` reconnects after transport state flips to `closed` / `failed`
- Re-issues last presence map after reconnect (so other peers see the right state)
- `RoomChannel.sendChat()` immediately appends an optimistic entry to history with `pending: true`; flips to `confirmed` on engine echo or `failed` on timeout
- New `chat-status` event: `{ id, status: "pending" | "confirmed" | "failed" }`
- Tests cover: socket drop mid-recording presence, optimistic echo + reconcile, fail timeout

**Open question:** chat sequence numbers (gap 7) — defer to consumer feedback. Add only if real misordering is observed.

## EPIC-21 — Recording streaming + `for=` attribute (NEW)

**Scope:** Make Recorder useful for live-upload scenarios (server-side recording via chunks) and remove the JS-only stream-binding requirement on the element.

**Gaps closed:** 9, 12.

**Depends on:** EPIC-18 (chunk buffer cap).

**Size:** M.

**Acceptance:**

- `defineUploader({ url, chunkSize?, headers? })` returns a sink. `Recorder.pipeTo(uploader)` forwards `dataavailable` chunks via `fetch` with `keepalive`. Backpressure: pauses recorder on 4xx / 5xx until consumer-defined retry resolves.
- `<forinda-recorder for="my-publisher">` resolves the target element's `mediaStream` automatically and records when started
- New element `<forinda-uploader>` slottable inside `<forinda-recorder>` for declarative upload destinations
- React: `useUploader(recorder, { url })`
- Tests cover: chunk → fetch round-trip, backpressure on error, target resolution by id

## EPIC-22 — Engine hardening: rate limits + chat persistence (NEW)

**Scope:** Server-side guards. Per-peer rate-limit tokens for `presence-update` and `chat`. Optional in-memory ring buffer of recent chat per room, replayed to late joiners.

**Gaps closed:** 8, 10.

**Depends on:** nothing (engine-only).

**Size:** S–M.

**Acceptance:**

- `defineSignalingEngine({ rateLimit: { presenceUpdatesPerSec, chatPerSec } })` throttles per peer; over-budget messages → `SignalingValidationError` with code `rate_limited`
- `defineSignalingEngine({ chatHistoryPerRoom: 50 })` keeps last N chats; new joiners receive a `chat-history` message right after `presence-snapshot`
- Both opt-in with sensible defaults (off / 0)
- Tests cover: burst limit, recovery after window, late-joiner replay

## Recommended order

1. **EPIC-18** (polish) — clears the easy-debt before anything else; small + fast.
2. **EPIC-9** (CI + npm publish) — unblocks adopters and gates everything from now on.
3. **EPIC-19** (`defineRoom`) — fixes gap #2, biggest pure-architecture improvement.
4. **EPIC-20** (resilience) — closes the production-readiness story.
5. **EPIC-21** (recording streaming) — completes the original recording ask.
6. **EPIC-22** (engine hardening) — server-side guards before traffic.
7. **EPIC-12** (moderation) — adopters with director needs.
8. **EPIC-8 finish** (browser + e2e tests) — once features are stable.
9. **EPIC-23** (docs) — once the architecture is settled.
10. **EPIC-14 / 15 / 16 / 17** — feature epics, picked by user demand.
